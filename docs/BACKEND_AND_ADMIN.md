# بک‌اند پیشنهادهای سفر و تنظیمات API (محیط آزمایشی)

## اجرا
- محلی: `npm run build && npm run build:server && PORT=3100 node server/dist/index.js` (فرانت ساخته‌شده و `/api/*` از یک سرویس).
- توسعه: `npm run dev` (Vite، پروکسی `/api` به پورت ۳۰۰۰) و `PORT=3000 node server/dist/index.js`.
- تست: `npm test` (کلاینت)، `npm run test:server` (سرور، با fetch ساختگی؛ هیچ تماس واقعی با Gemini/جست‌وجو انجام نمی‌شود).
- `railway.json`: build = `npm run build && npm run build:server`، start = `npm run start:api`. بازگشت: `buildCommand: npm run build`، `startCommand: npm start`.

## ذخیره‌سازی (آزمایشی)
فایل JSON در `DATA_DIR` (پیش‌فرض `data/`). روی Railway بدون Volume با هر استقرار پاک می‌شود. رابط `Store` (server/src/store/types.ts) async است و طرح PostgreSQL متناظر در `server/migrations/001_init.sql` آماده است؛ برای انتقال فقط باید یک پیاده‌سازی `Store` برای PostgreSQL نوشت (هنوز نوشته/آزمایش نشده).

## متغیرهای محیطی
| متغیر | کاربرد |
|---|---|
| `GEMINI_API_KEY` | کلید Gemini (اولویت بر کلید واردشده از رابط) |
| `TAVILY_API_KEY` | جست‌وجوی وب (Tavily) برای منبع‌یابی |
| `UNSPLASH_ACCESS_KEY` | جست‌وجوی تصویر Unsplash، فقط Access Key (Wikimedia بدون کلید) |
| `SECRETS_ENCRYPTION_KEY` | (≥۱۶ نویسه) فعال‌کنندهٔ ذخیرهٔ رمزنگاری‌شدهٔ کلید از صفحهٔ «تنظیمات API» |
| `ADMIN_TOKEN` | (≥۱۶ نویسه) اگر تنظیم شود همهٔ `/api/admin/*` به `Authorization: Bearer` نیاز دارد |
| `ADMIN_OPEN=true` | فقط تست: در production بدون ADMIN_TOKEN دسترسی بازِ ادمین را روشن می‌کند |
| `DATABASE_URL` | نشانی PostgreSQL (مثلاً Neon رایگان: `postgresql://…?sslmode=require`). اگر تنظیم شود همهٔ دادهٔ مدیریت (پیشنهادها، تنظیمات، کلیدهای رمزنگاری‌شده، رویدادها) در PostgreSQL ماندگار می‌شود و جدول‌ها هنگام شروع خودکار ساخته می‌شوند؛ وگرنه فایل JSON آزمایشی |
| `DATA_DIR` | مسیر ذخیرهٔ آزمایشی (Volume برای ماندگاری) |
| `DATABASE_URL` | فعلاً فقط برای `/api/ready`؛ هنوز دادهٔ پیشنهادها در PostgreSQL نیست |

## امنیت (وضعیت فعلی)
- هنوز **ورود ادمین واقعی نیست**. در development دسترسی بازِ آزمایشی است؛ در production بدون `ADMIN_TOKEN` یا `ADMIN_OPEN=true` همهٔ `/api/admin/*` با ۵۰۳ بسته است.
- ذخیرهٔ کلید از رابط در production بدون `ADMIN_TOKEN` مسدود است. کلیدها هرگز در پاسخ API (فقط ۴ نویسهٔ آخر)، لاگ یا فایل‌های build نمی‌آیند.
- پیش از انتشار عمومی: احراز هویت واقعی + نقش‌ها + ثبت اقدامات مدیر.

## چرخهٔ پیشنهاد
draft → pending_review → approved → published (و rejected با دلیل، archived). انتشار فقط با تصویر اصلیِ «تأییدشده» دارای مجوز و بدون پیشنهاد منتشرشدهٔ هم‌نام. ویرایش متنِ منتشرشده، انتشار را لغو می‌کند. هر ویرایش یک نسخهٔ جدید می‌سازد (مقایسه و بازگردانی در پنل).

## تحلیل رفتار و تبلیغات (تصمیم محصول)
- هر چهار رضایت (تحلیل ناشناس، تبلیغات شخصی‌سازی‌شده، اعلان‌ها، موقعیت) پیش‌فرض روشن‌اند و پنجرهٔ رضایت ندارند. ردیف «حریم خصوصی و رضایت» از صفحهٔ تنظیمات برداشته شده؛ صفحهٔ `/privacy` (مرور/لغو رضایت‌ها، مشاهده و حذف داده‌ها) با آدرس مستقیم همچنان کار می‌کند و منطق جمع‌آوری و ارسال فعال است. انتخاب صریح قبلیِ کاربر با تغییر پیش‌فرض‌ها بازنویسی نمی‌شود. پیش‌فرض‌ها هم با نسخهٔ سیاست (`POLICY_VERSION`) و زمان ثبت می‌شوند.
- جریان: رویداد → صف محلی (localStorage) → `POST /api/events` هنگام اتصال (بازگشت اینترنت، دیده‌شدن برنامه، هر ۶۰ ثانیه، عقب‌نشینی نمایی). رکوردهای رضایت (از جمله لغو) همراه می‌روند؛ سرور رویدادِ بعد از لغو را نمی‌پذیرد. `event_id` تکراری دوباره ثبت نمی‌شود.
- پیش از انتشار عمومی، سیاست حریم خصوصیِ قابل‌دسترس برای کاربر و الزامات فروشگاه‌ها/قوانین محل فعالیت را بررسی کنید؛ جمع‌آوری پیش‌فرضِ روشن ممکن است در برخی قوانین یا فروشگاه‌ها نیاز به رضایت صریح داشته باشد.

## اعلان تاریخ
`/settings ← نمایش تاریخ در نوار اعلان`: با کلیک کاربر اجازهٔ اعلان گرفته می‌شود و اعلان با `tag` ثابت نمایش/به‌روز می‌شود (هنگام باز شدن برنامه، بازگشت به برنامه، نیمه‌شب، و `periodicsync` در مرورگرهایی که اجازه می‌دهند). وب‌اپ نمی‌تواند اعلان غیرقابل‌حذف بسازد؛ برای اعلان واقعاً دائمی نسخهٔ اندرویدی لازم است.


## راه‌اندازی یک‌باره روی Railway بدون Volume
1. در Neon (neon.tech) یک پروژه بسازید و «Connection string» را کپی کنید.
2. در Railway → Variables این‌ها را یک بار بگذارید: `DATABASE_URL`، `SECRETS_ENCRYPTION_KEY` (رشتهٔ تصادفی ≥۱۶ نویسه) و `ADMIN_OPEN=true` (فقط تست) یا `ADMIN_TOKEN`.
3. از این پس کلیدهای Gemini/Tavily/Unsplash را از صفحهٔ «تنظیمات API» وارد کنید؛ رمزنگاری‌شده در PostgreSQL می‌مانند و با دیپلوی پاک نمی‌شوند.

## محتوای صفحهٔ اصلی (آیا می‌دانستید + موضوع‌های کاشی صفحهٔ دوم)
- ۹ موضوع (`server/src/feed/schema.ts` ⇄ `src/feed/topics.ts`)، هر کدام یک بخش جدا در پنل: «صفحهٔ اول: آیا می‌دانستید» و «صفحهٔ دوم: کاشی موضوعات» (حال‌وهوای امروز، این ماه وقت کجاست؟، پیشنهاد مخصوص تو، این هفته کجا بریم؟، تقویمی که برای سفر زندگی می‌کند، سفرهای کوچک، لیست آرزوها، هر روز یک کشف تازه).
- چرخه: تولید با هوش مصنوعی (جست‌وجوی وب فارسی + انگلیسی ← Gemini ← جست‌وجو و انتخاب خودکار تصویر) ← پیش‌نویس ← تأیید مدیر ← **صف انتشار** ← هر روز (به وقت تهران) یک کارت منتشر می‌شود. ورود به صف نیازمند تصویر اصلیِ دارای مجوز و حداقل یک منبع است.
- ذخیره‌سازی: یک مقدار KV با کلید `feed_v1` (بدون مهاجرت جدید؛ در PostgreSQL و فایل JSON کار می‌کند). API عمومی: `GET /api/feed`؛ مدیر: `/api/admin/feed/*`.
- برای منبع وب «جست‌وجوی وب» را در «تنظیمات API» روشن و کلید Tavily را وارد کنید؛ بدون آن کارت بدون منبع ساخته می‌شود و باید منبع دستی اضافه شود.
